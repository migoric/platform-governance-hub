# 信息架构与 UI

> 视觉语言照 deskbench 的样子做（玻璃卡片、折叠卡、分段控件、右侧 inspector 事实卡），
> 但**实现是 Rust + GPUI 重建**——那 1755 行 SwiftUI 组件一行都搬不过来（`architecture.md §2.1`）。
> 目标不变，路径变了：§3 是迁移清单，不是 import 清单。
>
> 产品形态参考 Accio Work：**以任务为单位，agent 是具名成员**。但不能把它整套搬过来——
> 规则引擎的结论必须留在一个「不经模型」的地方。所以是**两层**：任务层套在事实层上。

## 1. 两层与侧栏

### 1.1 为什么是两层

Accio 的形态是「一切收进会话」：报告在对话里长出来，任务是唯一入口。这个形态对开放式产出成立，
对合规不成立——`refactor-constraints.md §1.1` 要求 `finding.evidence.quote` 必须能在原文里按
`offset/length` 命中，对不上就丢弃。这个校验的落点不能是对话。

所以拆成两层，共享同一份快照与规则引擎：

| 层 | 谁产生 | 能否被模型改写 | 回答什么 |
|---|---|---|---|
| 任务层 | 人发起，agent 执行 | 是（草稿、解释、建议） | 我现在这件事做到哪了 |
| 事实层 | 规则引擎 + 采集 | **否** | 今天必须处置什么、依据什么 |

**任务层不另算一遍。** 任何显示出来的条数与金额，都来自事实层的 `summary` 或 `DashboardSelector`（§5）。
这条如果破了，任务里的数字和风险清单里的数字迟早对不上。

### 1.2 侧栏

```
任务                            ⌘1
  ├ 进行中
  ├ 已完成
  └ 定时任务                    ⌘⇧S

事实
  ├ 总览                        ⌘2
  ├ 风险清单                    ⌘3
  ├ 上架前检查                  ⌘4
  ├ 在售巡检                    ⌘5
  ├ 整改与复核                  ⌘6
  └ 规则与证据                  ⌘7

设置                            ⌘,
```

三段，对应三种意图：**正在做的事 / 要判断的事 / 配置**。

> 上面是目标形态。**现在能点的只有七个**：进行中 / 已完成 / 总览 / 风险清单 / 上架前检查 /
> 规则与证据 / 设置。定时任务、在售巡检、整改与复核还没做，侧栏把它们列出来但标「未实现」、
> 不写快捷键（`§4.1` 第 1 条）。

- 任务段回答「我现在在做什么」，总览回答「今天必须处置什么」。两者不是一回事：
  前者是已经开动的活儿，后者是还没人碰的风险。混在一起会让人以为「没任务 = 没事」。
- 原来的「规则库」与「证据中心」合并为「规则与证据」：它们回答的是同一个问题
  「这条结论有没有出处」，规则是条款出处、证据是材料出处。页内用 `SegmentControl` 切换。
- 一级入口从 9 个降到 8 个，且任务排第一。Accio 的入口密度是 5 个，我们比它多是因为
  事实层的每个面板对应一种明确的判断动作，不能为了对齐数字强行合并。

## 2. 每个面板回答什么问题

### 2.1 任务层

| 视图 | 唯一要回答的问题 | 数据来源 | 主视觉 |
|---|---|---|---|
| 任务列表 | 哪些活儿在跑、哪些卡住了？ | `~/.pgh/agent/` | 任务卡列表：目标一行 + 状态 + 耗时 + 参与的 agent |
| 任务详情 | 这件事做到哪了、结论是什么？ | provider 事件流 | 会话流：用户消息 → 思考折叠条 → 工具轨迹 → 产出块 |
| 定时任务 | 哪些事不用我记着？ | `~/.pgh/config.json` 的 `schedule` | 规则名 + 下次运行 + 上次结果 |

四种任务状态：`进行中` / `等待确认`（agent 到了决策点）/ `已完成` / `已中断`（降级或断线）。
**「等待确认」必须能从侧栏和 Dock 看到**，不能只在任务内部转圈。

任务详情的数据源是**会话投影**（`~/.pgh/agent/session.json`），不是事件流本身：
投影由 sidecar 从事件流算好（`agent/session.mjs`），UI 只摆。三条落地细节：

- 折叠条那一行写 `11 个事件 · 2 次工具 · 耗时未记录`。事件契约（v1）没有时间戳，
  耗时就是未知，**不许按事件条数估一个** —— M0 的 fixture 里那个「2 分 14 秒」是编的，已删。
- 归属行必须带「回放 / 真实分析」徽章（文字，不只是颜色）+ provider 自己给的免责原话。
  回放不许被渲染成任何像是真实分析的样子。
- 没有会话文件时给空状态说清缺什么，**不回落到旧的手写轨迹**。两套时间线必然分叉，
  而界面上没法标注「这一份是编的」。

任务卡的四个字段固定，不随任务类型变化：

```
┌──────────────────────────────────────────┐
│ 把上周新增的 12 条 blocker 逐条解释一遍      │  ← 用户原话首句，不改写成标题党
│ 等待确认 · 2 分 14 秒 · 条款研究员           │  ← 状态 / 耗时 / 参与的 agent
│ 真实数据                                   │  ← 来源标记：真实 / 回放
└──────────────────────────────────────────┘
```

**新建任务的三个模板**（对应 `New task`，不给空白输入框）：

1. 审查一批商品 → 自动带上当前筛选的 item 集合
2. 回答一个问题 → 自动带上当前选中条目
3. 生成一份报告 → 选模板 → 走报告撰写员

报告不再是一级面板。它仍然能导出 PDF / DOCX，但**出生地是某个任务**——这样「这份报告当时基于哪批数据」
天然可回溯，不需要额外做审计日志。

### 2.2 三个 agent 角色

| 角色 | 职责 | 工具面 | 产出 |
|---|---|---|---|
| 条款研究员 | 这条规则依据什么 | `rule_lookup` / `evidence_get` | 条款出处 + 原文引用 |
| 风险审阅员 | 这批风险要不要慌 | `snapshot_query` / `impact_estimate` | 分级解释 + 处置建议 |
| 报告撰写员 | 怎么写成给人看的东西 | `snapshot_query` | 报告草稿（进模板后导出） |

三条硬约束：

1. **三个角色的工具面都是只读的**（`agent-acl.md §7`）。写操作不进工具表。
2. **谁都不能产出 finding。** finding 只能由规则引擎产生；agent 只能解释已有 finding。
   这条决定了 agent 出错时最坏结果只是「解释得不好」，不会变成「凭空多一条风险」。
3. **角色名是归因，不是权威。** 界面上出现 agent 名字的地方，必须同时出现它的产出类型标记
   （解释 / 草稿 / 建议），见 §6。

### 2.3 事实层

| 面板 | 唯一要回答的问题 | 数据来源 | 主视觉 |
|---|---|---|---|
| 总览 | 今天必须处置哪几条？ | `summary` + findings 排序 | 4 个 KPI + 「最该介入」清单（3 条 blocker + 3 条最旧 required） |
| 风险清单 | 这批商品违反了哪些规则？ | `findings` | 表格式列表 + 严重度筛选 + 站点/类目分段 |
| 上架前检查 | 这个 SKU 能不能上？ | 本地单条 item + 规则 | 单条详情：通过/阻断 + 每条规则的证据 + 修改建议 |
| 在售巡检 | 规则更新后，哪些已上架的要重判？ | 新旧规则 diff → 重跑 | 「新增 N 条 / 消失 M 条」的差异视图，不是全量重列 |
| 整改与复核 | 哪几条还欠着、谁改的、谁批的？ | `actions.jsonl` | 按状态分列（待处理 / 已处理待复核 / 已豁免），每条带时间线 |
| 规则与证据 | 这条结论依据什么？ | `packs/<id>/rules/` + `evidence/` | 分段切换：规则（条款出处、正反例、impact）/ 证据（缩略图网格 + 被哪些 finding 引用） |

**「上架前检查」和「在售巡检」用同一份规则、同一个引擎**，区别只是入参集合与差异呈现。

M1 落地的是**只读第一版**：上架前检查按商品聚合成三态（需整改 / 待判 / 可上架），
规则与证据显示包级信息 + 每条规则的命中/待判战绩 + 待判原因分布。
点回原文、规则正文浏览、impact 预估的交互都还没做 —— 数据侧已经就绪（`pgh rules list --json`），
差的是 UI 交互，别在文档里假装已经有了。
这不是巧合，是为了保证口径唯一：同一条 SKU 在两个入口得到的结论必须逐字一致。

（原「报告」面板已并入任务层，见 §2.1。）

### 2.4 设置

| 视图 | 唯一要回答的问题 | 数据来源 | 主视觉 |
|---|---|---|---|
| 设置 | 现在用的是哪个 agent 服务、为什么不是更前面的那个、这次产出能不能当真实分析？ | `~/.pgh/agent/status.json`（`pgh agent status` 落盘） | 当前服务一行 + provider 三行（状态 / 契约版本 / 能力 / 归属）+ 两条限制 |

**这一屏不自己探测。** 它读的是 sidecar 探完一遍的结论，和「面板数字只算一次」同一条规矩：
窗口与终端各探一遍，迟早会出现「终端说 remote 没配、窗口说可用」。

三条渲染规矩（`agent-acl.md §13.5` 写了理由）：

- 握手失败的 provider **不展开能力行** —— 那是地板值，不是「不支持」；
- 归属三态：真实 / 回放 / **未声明**，未声明不借用回放的颜色；
- 两条限制必须写在屏上：握手通过**不代表账号已登录**；指定服务后阶梯不退让。

M2 落地的是**只读版**：能看见状态，不能点。切换入口是 `pgh agent use <id|auto>` ——
画一个点了没反应的分段控件比不画更糟。UI 交互层到位后再补选择控件。

## 3. 设计系统：照 deskbench 的目标，在 GPUI 里重建

左列是要复现的观感与行为，右列是 GPUI 侧的落点。**没有一项是「继承」，全部是重写**，
但重写时必须复现右列「难点」里写的行为，否则就是换了个更难看的版本。

| 目标（deskbench 的） | GPUI 落点 | 难点 / 取舍 |
|---|---|---|
| 玻璃材质（Liquid Glass） | 半透明底色 + 1px 高光边框 + 内阴影 | 真模糊要平台 backdrop，macOS vibrancy 不跨平台。**先做「半透明 + 高光」，不做真 blur**——跨端一致性比观感重要 |
| `PanelScaffold`（骨架 + 出图直排分支） | 一个 `Panel` 组件 + `RenderMode` 枚举 | 出图与真窗口是两条渲染路径，直排分支要各写一次 |
| `CollapsibleCard`（证据 / 条款 / 轨迹折叠） | 组件内自管展开态 | 展开要有动画，别做成瞬变 |
| `SegmentControl`（页内分段唯一实现） | 自绘分段条 | 键盘 ←→ 切换自己接 |
| `TrendCard` / 图表 | 自绘折线（全站只有「近 8 周新增违规」一处） | 不引图表库 |
| `LinedTextView` + JSON 着色 | 自绘行号 + 简易 tokenizer | 长文本要虚拟化 |
| Inspector 事实卡 | 右侧定宽栏 + 选中态订阅 | 点选不调模型（§4.1） |
| 离屏出图（`--render`） | 见 §8 | **GPUI 侧可行性待验证**，见 roadmap M0 风险 |

需要新写的五个控件（M0 只做前两个，后三个随面板到）：

1. **严重度徽章** —— 四档，带文字不只靠颜色
2. **任务卡** —— 目标一行 / 状态 / 耗时 / agent 组 / 来源标记，四行固定高度，列表用虚拟化
3. **证据引用串** —— `item → field → offset` 可点击跳转
4. **状态时间线** —— 处置留痕
5. **思考折叠条** —— `思考 2 分 14 秒 · 12 步`，默认收起，展开即工具轨迹

思考折叠条是参考 Accio 的 `Thought for 96s` 加的。价值不是"展示 AI 在思考"，而是**给出可审计的时间线**：
合规场景里人要能回答「这 2 分钟它到底查了什么」，所以展开后必须逐条列出工具调用，而不是一段总结。

## 4. 交互约定

1. **点选不花钱。** 列表点选只更新 inspector 与选中态，不触发任何模型调用。任务必须显式新建。
2. **一条 finding 三个入口。** 列表行 → inspector 事实卡 → 任务（同一条被自动带入上下文）。
3. **结论与证据同屏。** 任何显示「不合规」的地方，旁边必须能展开看到 `quote` 与条款出处；
   做不到就在设计上不许出现这个结论。
4. **空状态要说清为什么空**：没采集 / 规则没跑 / 这条真的没问题 —— 三种文案不同，不能都写「暂无数据」。
5. **批量操作只给「忽略」和「标记待人工」**，不给「全部修复」。合规没有一键修复，违和。
6. **任务可续，不重放。** 断线、降级、关窗后重开，任务从最后一个事件继续；已完成的 `tool_call`
   不重新执行（依赖 `seq`，见 `agent-acl.md §12.2`）。重放等于重复计费。
7. **决策点要打断。** agent 需要人确认时发 macOS 本地通知 + Dock 徽章，不在应用内静默等待。
   对应 Accio 的移动端推送——本项目不做移动端，用系统通知替代。

### 4.1 什么能点（M2 起接上）

场景树里每个节点可以挂一个 `Action`（`ui/scene.rs`）。**挂没挂是「能不能点」的唯一依据**，
所以「界面上看着能点、点了没反应」在结构上不成立 —— 这份清单也写进结构快照，
把某处改成不可点、或者指向换了，基准会红。

| 位置 | 动作 | 落到哪 |
|---|---|---|
| 侧栏七个入口 | `Action::Nav(slug)` | `View::from_action` 翻译成视图，高亮跟着走 |
| 任务卡 | `Action::OpenTask(id)` | 打开该任务详情，并把 id 记进选中态 |
| 详情里的折叠条 | `Action::ToggleTimeline` | 展开 / 收起会话时间线 |

三条规矩：

1. **没做的入口标「未实现」，右侧不写快捷键。** 侧栏保留设计里定下的入口（定时任务 /
   在售巡检 / 整改与复核），但没有动作 —— 点不动的东西要在点之前说清楚，而不是点了才知道。
2. **认不出来的动作什么都不做。** `View::from_action` 返回 `None` 就到此为止，不猜一个视图顶上。
3. **选中了 A 不许显示 B。** 详情拿 `selected_task` 比对 `task-detail.json` 的 `taskId`，
   对不上就给空状态并写明缺哪份文件 —— 不拿唯一那份详情冒充。

还没接的一并写在这里，免得下次以为它们能用：侧栏的 ⌘1–⌘7 / ⌘, 键位（标签在画，分发未注册）、
分段控件、inspector 结论跳转、`New task`。

## 5. 数字口径

和 deskbench 一样：**面板数字只有一个计算处** —— `State/DashboardSelector.swift`（纯值类型、可测）。

- sidecar 负责算 `summary`（跨 item 的聚合）
- Selector 负责按筛选条件分组与排序
- View 里禁止出现 `findings.filter { ... }.count`

任务层的耗时与成本是**事件流的聚合**（`usage` 求和、时间戳相减），同样不在 View 里算：
由 sidecar 的 `projectSession()` 算一次写进会话投影，UI 侧 `models/session.rs` 只负责文案。
拿不到的量保持 `null`，显示成「耗时未记录 / 用量未上报 / 成本 —」—— 落成 0 就是把
「不知道」伪装成「没有问题」。

这条规矩的真实收益：总览说「3 条 blocker」，点进去风险清单筛选后也必须是 3 条，
任务卡上写「12 条 blocker」时也必须是同一批。三处各算一遍，迟早对不上，然后整个工具的数字就没信用了。

## 6. 视觉规则（继承 + 两条新增）

继承 deskbench 四条：只读优先 / 颜色分级 / 不确定就明说 / 语义色只出现在内容里。

新增第五条：**AI 结论与规则结论在视觉上必须可区分。**

- 规则引擎结论：实心徽章 + 「依据：条款 3.2.1」
- agent 语义结论：带 AI 角标 + 「模型判断，需人工确认」+ 可展开查看原文引用
- 人工作出的结论：带头像/时间，写「某人 · 2026-11-06」

三者混在一起排版可以，但**不能长得一样**。用户有权知道自己看的是机器算的、模型猜的，还是人拍的。

新增第六条：**agent 的名字只做归因，不做背书。**

任务卡与会话里出现「条款研究员」时，同一行必须带产出类型（解释 / 草稿 / 建议），
且不出现任何看起来像判定结论的措辞。理由很实际：Accio 那种「有名字的 AI 同事」会让人自然放松警惕，
而这里的一条结论如果被误当成规则判定，是要写进合规声明的。

## 7. 可访问性（最低要求）

- 严重度不靠颜色单独表达：徽章带文字（阻断 / 必改 / 建议 / 留意）
- 深色模式下文字对比度 ≥ 4.5:1（deskbench 踩过：染色玻璃 + 白字 = 看不见；GPUI 里没有系统材质兜底，更容易翻车）
- 全键盘可达：列表 ↑↓ 选择、打开 inspector、新建任务、进入任务、Esc 收起
- 「等待确认」状态不能只靠颜色：任务卡带文字徽章，且 Dock 有角标
- **快捷键要按平台换标签**：macOS 显示 `⌘N`，Windows 显示 `Ctrl+N`。文档里写 `⌘` 只是沿袭，
  代码里必须走一个 `Shortcut` 抽象，不能把 `⌘` 硬编码进文案
- ⚠️ **AccessKit 是待验证项**：GPUI 的无障碍树在 macOS 上覆盖到什么程度没有实测过
  （roadmap M0 风险）。键盘可达我们自己能保证，读屏能不能用要看验证结果，**别在验证前对外承诺**

## 8. UI 回归

目标不变：**改版前后各跑一次，比结构不比观感。** 但 GPUI 0.2.2 的实际情况（已查源码）是：

- **没有离屏出图 API**：`gpui-0.2.2/src` 里没有 `render_to_image` / `RenderImage` 一类接口；
- 唯一的截屏能力是 `screen-capture` feature 包着的 `screen_capture_sources`
  （macOS 12.3+，截的是真实屏幕，**需要屏幕录制权限**）；
- `TestAppContext`（`test-support` feature）能跑窗口逻辑，但没有「拿到一帧像素」的公开入口。

所以回归基准改成**结构快照**，M0 就按这个验收：

1. `cargo run -p hub -- --render <目录> [--appearance dark]` 对每个视图输出一份 JSON：
   节点树（类型 / 层级 / 关键样式）+ 可见文本 + 数据源条数。
   确定性来自固定 fixture（`fixtures/snapshot.json`、`fixtures/tasks.json`、`fixtures/task-detail.json`）。
   已提交的基准在 `GovernanceHub/fixtures/structure/`，11 份、文件名字典序即视图顺序（全 ASCII，
   Windows 上文件名编码不惹事）。`--check-baseline` 逐文件比字节，`scripts/check.sh rust` 会调它。
2. 比结构的方式：同一视图两份 JSON 做 diff（`--check-baseline` 不一致时退出码 1）。
   改版是自己想要的 → 重新生成基准（`--render fixtures/structure`）；
   不是 → 说明布局或文案被误改。**这比像素 diff 更抗字体光栅化差异**，本来就是跨平台唯一可行的那条。
3. PNG 只在**人工核对**时出：起真窗口 → `screen-capture` 抓图。要屏幕录制权限，不入库、不进 CI。
4. 基准只在 macOS 生成。Windows 侧跑同一个 `--render`，比 JSON——结构一致才是跨端的要求，
   像素一致不是（字体不一样，追求像素一致等于自找麻烦）。

deskbench 踩过的两个坑在 GPUI 里换了形状：

| 坑 | GPUI 里的对应形态 |
|---|---|
| `ImageRenderer` 不实体化 `ScrollView` | 结构快照拿不到 `uniform_list` 懒渲染出的行——所以快照里记「数据源条数」而不是「渲染出的行数」，否则四态任务列表永远只有 3 行 |
| 画不出 Liquid Glass | 我们本来就不做真 blur（§3），但半透明底色与高光的合成结果仍然只能靠人眼看 PNG |

新增两个必须出快照的视图：**任务列表**（四种状态各一份）与**任务详情**（思考折叠条的收起/展开两态）。
任务详情用 `GovernanceHub/fixtures/task-detail.json`，保证每次出图内容一致；
M2 接上 `replay` provider 后，改由 provider 回放同一份 fixture，卡面不动。

M2 又加一份：**设置**（`11-settings.json`），数据来自 `GovernanceHub/fixtures/agent-status.json`。
这份 fixture 特意是「离线降级到回放」的场景（remote 未配置、claude-cli 未安装），
因为那是最常见的一种真实状态，也最能验证「回放必须标出来」。
